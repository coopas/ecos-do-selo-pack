# Ecos do Selo — Plano 3: Lore, Quests e Loja — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lore completa em PT-BR e uma linha de quests FTB contínua (~450 quests) do Prólogo ao final, com loot surpresa em 4 raridades, moeda, loja, páginas de diário e chefe final por ritual. Tudo gerado a partir de fontes YAML, validado contra os dumps reais do jogo e carregado sem erro pelo FTB Quests.

**Architecture:** As quests são escritas em `quests/src/*.yaml`, uma fonte legível por capítulo. O `tools/questgen.py` gera o SNBT do FTB Quests em `pack/config/ftbquests/quests/`, com IDs determinísticos (hash do slug), o que deixa diffs estáveis. O `tools/questcheck.py` valida tudo contra `build/registry_dump.json` e `build/recipe_dump.json`. Tasks "qualquer variante" usam o item-filtro do FTB Filter System gerado por `makeTagFilter`; a correspondência é provada em jogo pelo dump dev.

**Tech Stack:** FTB Quests 2001.4.x + FTB Filter System 20.x, KubeJS 6, Occultism (ritual), L_Ender's Cataclysm (chefe), Python 3.12 + PyYAML 6 + pytest, ferramentas dos Planos 1–2.

**Spec:** `docs/2026-11-03-ecos-do-selo-design.md` (§5 lore/atos, §6 quests, §8 imagens, §9 QA, §10) · Planos anteriores: `2026-11-03-fundacao.md`, `2026-11-03-conteudo.md`

## Global Constraints

- Todo texto do jogador em **PT-BR**, tom **sombrio/mistério**, com a lore revelada aos poucos e nunca em textão: no máximo ~4 linhas por descrição de quest; trechos maiores vão para as páginas de diário.
- **Regra de IDs (pedido explícito do usuário):** task de item usa **tag** sempre que existir variante equivalente (camas, troncos, tábuas, lã, mudas, vidro, lingotes/pós/placas `forge:*`, etc.). Item exato só quando a quest exige aquele item específico. Sem NBT exigido sem motivo.
- **Progresso individual** (times de 1 pessoa no FTB Teams); itens compartilháveis.
- Ordem dos atos e travas do Plano 2: Prólogo → I (Create, GT Steam/LV, Twilight; chefe Lich) → II (Ars, Iron's, Occultism, Undergarden/Deeper and Darker; Warden) → III (HV→EV, Aether/Blue Skies com Chave Celeste; Sun Spirit) → IV (Ad Astra, EV→IV/LuV; Ignis) → V (ProjectE, LuV→ZPM+, Artefato, chefe final).
- Escala: **~450 quests** (faixa aceitável 400–600); meta de ~300 h por jogador.
- Recompensas: **caixas de loot em 4 raridades** (comum, rara, épica, lendária), **Fragmento de Eco** (moeda), **páginas de diário**, e XP.
- Imagens definitivas chegam no Plano 4. Aqui, ícones de capítulo e quest usam itens do jogo; o campo `image` fica reservado e vazio.
- Nada de publicar/push sem o usuário pedir (memória `publicacao-github`).

## Review Focus

- **Quest impossível**: item sem receita nem fonte natural, tag vazia, entidade/dimensão inexistente. `questcheck` falha (Task 2) e `test_all_quests_obtainable` roda em todo capítulo.
- **Beco sem saída**: dependência em ciclo ou quest inalcançável a partir do Prólogo, ou capítulo trancado por quest de outro ato posterior. `test_graph_acyclic_and_reachable` + `test_act_order_respected` (Task 2).
- **Task exige variante específica** (ex.: cama vermelha). `test_no_variant_specific_items` (Task 2) checa contra a lista de tags de variante.
- **FTB Quests rejeita o SNBT em silêncio** (quest some do livro). O boot compara as contagens que o FTB loga com as da fonte (Task 1, `test_ftbquests_loaded_counts`), e o `log_scan` pega erros de parsing.
- **Loja ou loot quebrando a economia** (moeda infinita, loja vendendo item de trava). `test_shop_never_sells_gates` e `test_coin_budget_per_act` (Task 4).

## Estrutura de arquivos

```
quests/
  src/00_prologo.yaml ... 05_ato5.yaml, side_*.yaml, loja.yaml, diario.yaml
  naturals.yaml          # itens obtidos sem receita (minérios, drops, loot) — fonte de "obtível" para o validador
  variant_tags.yaml      # tags de variante: se um item pertence a uma, a task deve usar a tag
  reward_tables.yaml     # caixas comum/rara/épica/lendária
docs/lore.md             # bíblia da lore (aprovada pelo usuário na Task 3)
tools/questgen.py        # YAML -> SNBT (pack/config/ftbquests/quests/**)
tools/snbt.py            # serializador SNBT
tools/questcheck.py      # validador (IDs, obtível, grafo, variantes, ordem dos atos)
pack/kubejs/server_scripts/dev/quest_selftest.js   # prova em jogo os filtros de tag e carrega contagens
pack/kubejs/data/ecos/... # ritual do chefe final (Occultism), lore books
tests/test_snbt.py, test_questgen.py, test_questcheck.py, test_rewards.py, test_chapters.py, test_final_boss.py
```

### Formato da fonte (fixado na Task 1)

```yaml
chapter: ato1                 # slug -> filename e ID
title: "Ato I — Ferrugem e Engrenagens"
icon: create:cogwheel
group: atos                   # atos | caminhos | loja | diario
act: 1                        # 0 = prólogo; side chapters também declaram o ato em que abrem
quests:
  - slug: primeira_engrenagem
    title: "A primeira engrenagem"
    desc: ["Uma linha curta.", "Outra."]
    icon: create:cogwheel     # opcional
    x: 0
    y: 0
    shape: hexagon            # opcional
    deps: [prologo/abrigo]    # slug local ou "capitulo/slug"
    tasks:
      - item: create:cogwheel        # item exato
        count: 4
      - tag: minecraft:logs          # vira item-filtro do FTB Filter System
        count: 16
      - kill: twilightforest:lich
      - dimension: twilightforest:twilight_forest
      - checkmark: true
    rewards:
      - coins: 3                     # Fragmento de Eco
      - loot: comum                  # caixa da reward table
      - xp_levels: 2
      - item: ecos:pagina_diario_03  # opcional
    repeatable: false
```

### Task 2: Validador de quests (`questcheck`)

**Files:** Create `tools/questcheck.py`, `quests/naturals.yaml`, `quests/variant_tags.yaml`, `tests/test_questcheck.py`; Modify `registry_dump.js` (adicionar `dimensions`).

**Interfaces:**
- Produces `questcheck.check(chapters, reg, rec, naturals, variant_tags) -> list[str]` (vazio = ok), com as regras:
  1. todo item/tag/entidade/dimensão existe (dimensões vêm do dump: `server.levelKeys()`);
  2. **obtível**: item task exato tem receita no dump **ou** está em `naturals.yaml` **ou** é drop do `boss_drops.json` **ou** é recompensa de quest anterior; tag task tem ≥1 membro obtível;
  3. **variante**: item exato que pertence a uma tag de `variant_tags.yaml` é erro, salvo `allow_exact: "<motivo>"`;
  4. **grafo**: deps existem, sem ciclo; toda quest é alcançável a partir de `prologo/despertar`;
  5. **ordem dos atos**: uma quest de capítulo com `act: N` não pode depender de quest com `act > N`;
  6. toda quest tem ≥1 recompensa; título e desc não vazios; desc ≤ 4 linhas.
- `naturals.yaml`: listas por categoria (`ores`, `mob_drops`, `plants`, `structure_loot`, `fluids_buckets`, `boss_drops`), cada item com comentário da fonte.
- `variant_tags.yaml`: no mínimo `minecraft:beds, logs, planks, wool, saplings, leaves, wooden_slabs, wooden_stairs, wooden_doors, boats, banners, candles, terracotta`, `forge:glass`, `forge:glass_panes`, `forge:dyes`, `forge:chests/wooden`.
- [ ] **Step 1: Testes que falham** (fixtures pequenas): `test_missing_item_reported`, `test_unobtainable_item_reported`, `test_red_bed_exact_rejected` (cama vermelha exata → erro citando `#minecraft:beds`), `test_allow_exact_with_reason_ok`, `test_cycle_reported`, `test_unreachable_reported`, `test_act_order_violation_reported`, `test_quest_without_reward_reported`.
